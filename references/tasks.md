# Task cards and troubleshooting

Cards are UTF-8 JSON generated by Codex from the user's authorized task. Resolve root to an existing absolute directory on the current machine. Example fields below show a task shape; replace project paths and the verifier with actual resources.

```json
{
  "id": "review-config-001",
  "root": "/absolute/project",
  "task_type": "review",
  "scope": "Read-only review of error handling in src/config.js.",
  "prompt": "Report concrete error-handling defects with file/line evidence. Only inspect the specified file.",
  "result_file": ".handoff/results/review-config-001.json",
  "max_turns": 30,
  "timeout_s": 300,
  "verify": ["node", "checks/verify-review.cjs", ".handoff/results/review-config-001.json"]
}
```

`id` contains lowercase letters, digits, and hyphens, begins with a letter/digit, and is at most 64 characters. Every attempt needs a new ID and absent result file. `result_file` resolves inside root, outside `.handoff/jobs`; parent directories are created. Existing ancestors are resolved and dangling links are rejected. These checks reduce accidental redirection, not malicious concurrent path replacement.

`verify` is a required executable/argument array, run without a shell from root, with a separate 60-second timeout. Codex controls the verifier; exclude it from worker edits. For shell scripts supply the interpreter explicitly, especially Windows cmd/PowerShell wrappers. A verifier should independently check facts or behavior, not merely file existence or the worker's assertions.

Explicitly choose task_type for new cards: investigation, log_analysis, review, and extraction default to read_only; isolated_edit defaults to edit. Legacy cards without task_type retain edit behavior. Read-only reports are saved by the parent from final response text; edit reports are written by the worker. See [advanced tasks](advanced-tasks.md) for mode, stdin, schema, and resume details.

Optional `model` overrides the configured user preference for this invocation. With no card override, a resume retains the parent model and a new task uses the local configured model. An unconfigured new task needs setup or an explicit card model. There is no service/model fallback. Inspect `requested_model`, `model_source`, `reported_models`, `request_model_ids`, and `request_model_names`; empty arrays mean missing evidence. Model prose is not proof.

`timeout_s` and `max_turns` override local defaults, subject to 1..1800 seconds and 1..200 turns. CLI exit 0 plus empty stdout on exhausted turns is a failure, with `cli_failure_reason=max_turns_exceeded` when stderr matches the known diagnostic. Whole CLI budget, schema check, verifier, and cleanup are separate; total host run time can exceed timeout_s. See [mechanisms](mechanisms.md).

Optional `allowed_tools` supplies narrow session-only rules through `--allowedTools`. It neither changes global permissions nor provides an OS sandbox. Read-only cannot grant shell/write access. For authorized edit-mode checks, a stable command might use `PowerShell(node checks/check.cjs)`; inspect parser normalization before assuming quoted commands match.

State, card, stdout, stderr, schema logs (if used), and verifier logs are stored under `<root>/.handoff/jobs/<id>`. Logs can contain task content: keep them out of public releases. The chain's first job contains chain.json and, while active, session.lock. `status` reads state without rerunning checks. A running PID may have been reused; `runner_alive` is not a complete child-process health check. Assess remaining processes and artifacts before handling stale locks or retrying.

Task executor exit codes: 0 accepted by automated checks; 1 execution/validation failed; 2 card/environment error; 3 explicit structured authentication error or locally unavailable credentials; 4 status still running; 5 unknown task. Authentication-looking words in report prose or stderr alone do not establish a CLI authentication failure. Inspect evidence without printing secret values. Content review remains Codex's responsibility.
